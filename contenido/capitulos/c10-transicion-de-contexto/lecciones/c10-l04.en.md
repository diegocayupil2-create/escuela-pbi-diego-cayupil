## The idea

Context transition has a cost: for every row of the iterator, DAX builds a new filter context. On a 300-customer dimension you won't notice; on a fact table with millions of rows, you will.

[[diagrama c10-d04]]

## Example

With `[Costo] = SUMX ( fact_ventas, fact_ventas[cantidad] * RELATED ( dim_producto[costo_unitario] ) )`, these two margin measures return the same result if every line is unique, but they don't cost the same:

```dax
Margen lento =
SUMX ( fact_ventas, [Ventas] - [Costo] )

Margen rápido =
SUMX (
    fact_ventas,
    fact_ventas[monto_neto]
        - fact_ventas[cantidad] * RELATED ( dim_producto[costo_unitario] )
)
```

The first runs two transitions per sales line. The second calculates with columns, row by row, without creating new contexts, and is usually much faster.

## Rule of thumb

- Iterate the smallest table that answers the question: `dim_cliente` or `VALUES ( dim_cliente[cliente_id] )`, not `fact_ventas`.
- Use measures inside the iterator when you need the value **per** customer, product or month.
- Measure before optimizing: in chapter 24 you'll see the difference in milliseconds with DAX Studio.
