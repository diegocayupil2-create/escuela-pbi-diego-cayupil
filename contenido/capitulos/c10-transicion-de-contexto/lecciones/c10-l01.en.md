## The idea

When DAX walks a table row by row, there is a **row context**: it knows which row it is on, but that doesn't filter anything. **Context transition** is what `CALCULATE` does: it takes the current row and turns it into a **filter context**, that is, real filters on the model.

## Example

In the `dim_cliente` table, create two calculated columns (Table tools → New column):

```dax
Ventas sin CALCULATE = SUM ( fact_ventas[monto_neto] )
Ventas con CALCULATE = CALCULATE ( SUM ( fact_ventas[monto_neto] ) )
```

The first shows the same number on every row: the company total. Each customer's row context doesn't filter `fact_ventas`. The second shows what each customer bought: `CALCULATE` turned the row into a filter on `dim_cliente`, and that filter travels through the relationship to `fact_ventas`.

## In the business

This is how you get each customer's purchases without writing one query per customer. It's the basis for rankings, segments and alerts.

## Watch out

Context transition filters by **every** column of the row, not just the key. That's why you should iterate tables with one unique row per item, like dimensions. You'll see why in lesson 3.
