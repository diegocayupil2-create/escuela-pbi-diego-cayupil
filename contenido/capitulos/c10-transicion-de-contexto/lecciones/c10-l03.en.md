## The idea

Context transition filters by the values of **every** column in the current row. If a table has two identical rows, each one «sees» both. When you iterate it and call a measure, each duplicate gets counted more than once.

[[diagrama c10-d03]]

## Example

`fact_ventas` has no key and contains two identical lines of $100,000:

```dax
Ventas por línea = SUMX ( fact_ventas, [Ventas] )
```

On each of the two rows, `[Ventas]` filters the rows equal to the current one: it finds both and returns $200,000. `SUMX` adds 200,000 + 200,000 = $400,000. If the two lines were a single sale duplicated by mistake, the right answer was $100,000, and even `[Ventas]` on its own already shows $200,000.

## How to avoid it

- Give the fact table a key at the source (a line id) and remove there the duplicates that are errors.
- Don't call measures inside an iterator over the fact table. Use the column directly, like `SUM ( fact_ventas[monto_neto] )`, or a `SUMX` over columns if you need a row-level calculation.
- Iterate dimensions, with one row per customer or product, not facts.
